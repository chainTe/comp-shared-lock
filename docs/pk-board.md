# PK 留言板（草案）

一个频道，两个阵营，谁留言多谁赢。

## 概念

- 一个频道：`name = "…vs…"`，`channel_hash` 按名字算（不变）
- 两个 cell：A 方一个、B 方一个；各自 data 里的 `sponsor` 写自己的阵营名
- 用户用哪边的 cell 发，就算哪边得分

## 链上模型

沿用 COMP Shared Lock，不改合约。

| 对象 | 内容 |
| --- | --- |
| 频道 | `args = channel_hash ‖ max_fee`，两边相同 |
| A cell | data = comp-meta v2（name, kind=chat, sponsor="A 队"） |
| B cell | data = comp-meta v2（name, kind=chat, sponsor="B 队"） |

两个 cell 互不干扰：各自满足"一个输入、一个后继、data 不变"，天然两条并行通道。

## 留言 payload

`extensions` 里放：

```json
{ "pk": 1, "side": "A", "text": "加油！", "w": 1 }
```

- `side` 是 `A`/`B`，必须和发出它的 cell 阵营一致，否则客户端不计分
- `w` 是一条值几分，默认 1，上限 9
- 匿名或签名都行；签名的话前端能显示"某某某说"

## 计分

前端扫这个频道的全部消息，按 `side` 累加 `w`。

data 冻结、消息不可删，这份账谁都改不了；不同客户端算出来必须一致。

## 防刷

链上没有身份，谁都能刷。客户端做三条降噪：

1. 同一作者（有签名时）每 10 个区块最多计 3 分
2. 匿名的按 `text` 去重，完全重复的只计一次
3. 分数条同时显示"总条数"和"去重分数"，不藏

## 截止

前端配置一个 `end_height`，到高度后分数冻结、只读。链上不用额外规则。

## 展示

- 顶部拔河进度条：`A 52% — 48% B`
- 下面两边留言流，最新在前
- 每条显示阵营色、时间、是否匿名

## 限制

- 一个 cell 一个区块只能过一笔，两边各自排队
- 消息删不掉，刷屏只能前端过滤
- "A 队" cell 谁都能建，前端以创建时登记的那个为准

## 开放问题

- `w` 要不要和 cell 剩余容量挂钩
- 平局怎么展示
- 要不要按天分赛季
